# Benchmark results: CPython vs Typhon

Generated by `benchmarks/run.ps1`. The same source file runs on both runtimes; "Same result" confirms both printed identical output.

- CPU: Intel(R) Core(TM) Ultra 9 285HX (24 cores / 24 threads), 63 GB RAM
- OS: Microsoft Windows 11 Pro
- Typhon: .NET SDK 11.0.100; each program compiled once with `typhon build --strict` (`--permissive` for *_untyped*) and run with `dotnet app.dll`
- CPython: Python 3.15.2
- NumPy: NumPy 2.5.5 + scipy-openblas 0.3.34.237.2; Typhon uses Typhon.NumPy (TensorPrimitives SIMD)
- Method: median of 5 runs per configuration. Times are the hot section, measured with time.perf_counter() inside each program. RAM is the peak working set of the whole process. Process is end-to-end wall-clock time (startup + program).
- Typhon compile time (`typhon build`, not included above): median 1,348.5 ms per program
- Typhon Native AOT: `typhon build --aot` (.NET ILCompiler, OptimizationPreference=Speed, InvariantGlobalization); median build time 4,767.3 ms per program. Programs that use dynamic values cannot be compiled ahead of time and show n/a (dynamic).
- Date: 2026-11-20

## numpy: CPython + NumPy vs Typhon + Typhon.NumPy

Threading decides these results, so both sides run in two configurations. NumPy's element-wise ufuncs are single-threaded; its matmul and linear algebra use OpenBLAS threads (OPENBLAS_NUM_THREADS=1 makes NumPy fully single-threaded). Typhon.NumPy parallelizes element-wise work above 131,072 elements and its matmul (TYPHON_NUMPY_THREADS=1 makes it single-threaded). "Best vs best" divides NumPy's faster configuration by Typhon's faster configuration. RAM is measured in the default configurations.
