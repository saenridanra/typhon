# Benchmark results on Linux: CPython, Codon, Pythran and Typhon

Generated by `benchmarks/linux/run_linux.sh`. The same source files as `benchmarks/run.ps1` (Windows); "Same result" confirms every tool printed CPython's result line.

- CPU: Intel(R) Core(TM) Ultra 9 285HX (24 logical CPUs visible), 11 GB RAM visible to Linux
- OS: Ubuntu 26.04 LTS on WSL2, kernel 6.18.33.2-microsoft-standard-WSL2
- CPython: Python 3.15.2; NumPy 2.5.5 + scipy-openblas 0.3.34.237.2
- Codon: 0.20.7; `codon build -release -exe` (LLVM, targets the host CPU; default `--numerics=c`); Codon's own NumPy implementation, BLAS/LAPACK: OpenBLAS 0.3.33 statically linked into libcodonrt.so (ILP64, default threads)
- Pythran: 0.19.0; kernels compiled with `pythran -O3 -march=native` using CXX=clang++ (Ubuntu clang version 21.1.8 (6ubuntu1)) plus Python's own compile flags; driver runs on the same CPython
- Typhon: commit 5af49f5 + local changes in src/; .NET SDK 11.0.100, runtime 11.0.0; `typhon build --strict` (`--permissive` for *_untyped*) run with `dotnet app.dll`; Typhon.NumPy (TensorPrimitives SIMD)
- Typhon Native AOT: `typhon build --aot` (.NET ILCompiler, OptimizationPreference=Speed), linked with Ubuntu clang version 21.1.8 (6ubuntu1); default configuration only. Programs that use dynamic values show n/a (dynamic).
- Method: median of 5 runs per configuration. Times are the hot section, measured with time.perf_counter() inside each program. RAM is the peak resident set (max RSS, `/usr/bin/time -f %M`) of the whole process. Process is end-to-end wall-clock time of the whole process (startup + program). Build steps run once per program before timing and are not included.
- Compile time per program (median, not included above): Codon 4,271.2 ms (28 programs) · Pythran 1,630.5 ms (18 programs) · Typhon 1,363.9 ms (29 programs) · Typhon AOT 3,838.9 ms (25 programs)
- Date: 2026-11-20

Cells show the hot-section time and, in parentheses, the speed-up versus CPython ("4.0x" = four times faster). n/a cells are explained at the end.

## Notes on comparability

- Pythran compiles only the exported kernel; the driver, setup code and timing run on CPython. Arguments and return values cross the Python/C++ boundary on every call: Python lists are converted to C++ containers (and returned lists back), which is included in the hot-section time (dot, movavg: 10M / 5M-element lists; matmul: a 200x200 result). Every Pythran extension module imports NumPy when it loads, so Pythran's process time and RAM include a NumPy import even for pure-Python kernels.
- Codon compiles the whole program with 64-bit machine integers (no arbitrary precision; overflow wraps) and C numerics by default (`--numerics=c`). None of these programs overflows, and every result line is compared with CPython's.
- BLAS: CPython + NumPy uses NumPy's bundled scipy-openblas, Codon its own statically linked OpenBLAS, Typhon.NumPy no BLAS (managed TensorPrimitives code). Pythran's NumPy support is its own C++ expression templates (none of the Pythran kernels here calls BLAS).
- Code generation targets: Codon and Pythran (-march=native) use the host CPU's full instruction set; the .NET JIT also targets the host CPU; Native AOT targets the ILCompiler's default instruction-set baseline.
