# Benchmark results on battery power: CPython vs Typhon

Generated by `benchmarks/run.ps1 -Output RESULTS_BATTERY.md` like [`RESULTS.md`](RESULTS.md), but with the laptop
**running on battery**. Compare the two files to see what battery mode costs. This run also has what `RESULTS.md`
predates: whole-program type inference (`nbody_untyped`), the CLI published with ReadyToRun, and the "One-off runs"
table with `typhon run` on a first run, with the compile server and from the script cache. The same source file runs on
both runtimes; "Same result" confirms both printed identical output.

- CPU: Intel(R) Core(TM) Ultra 9 285HX (24 cores / 24 threads), 63 GB RAM
- OS: Microsoft Windows 11 Pro
- Power: battery (77%) at the start, battery (72%) at the end; Windows power plan: Balanced
- Typhon: .NET SDK 11.0.100; CLI published with ReadyToRun; each program compiled once with `typhon build --strict` (`--permissive` for *_untyped*) and run with `dotnet app.dll`
- CPython: Python 3.15.2
- NumPy: NumPy 2.5.5 + scipy-openblas 0.3.34.237.2; Typhon uses Typhon.NumPy (TensorPrimitives SIMD)
- Method: median of 5 runs per configuration. Times are the hot section, measured with time.perf_counter() inside each program. RAM is the peak working set of the whole process. Process is end-to-end wall-clock time (startup + program).
- Typhon compile time (`typhon build`, not included above): median 984.6 ms per program
- Typhon Native AOT: `typhon build --aot` (.NET ILCompiler, OptimizationPreference=Speed, InvariantGlobalization); median build time 6,098.4 ms per program. Programs that use dynamic values cannot be compiled ahead of time and show n/a (dynamic).
- Date: 2026-11-20

## One-off runs: compile time included

Python scripts are often run once. `typhon run` is the equivalent of `python script.py` and has three situations: the first run compiles in the process (parse, infer types, Roslyn); while you work, a background compile server keeps the compiler warm and compiles instead; an unchanged script that ran before comes from the script cache without compiling. `typhon build` compiles once to a .dll (`--aot`: a native .exe). The CLI is published with ReadyToRun. All times are end-to-end process wall-clock times (median of 5 runs; builds measured once). "Break-even runs": the number of runs after which building once and running the compiled program is cheaper than running CPython every time ("never": the compiled program is not faster than CPython).

## numpy: CPython + NumPy vs Typhon + Typhon.NumPy

Threading decides these results, so both sides run in two configurations. NumPy's element-wise ufuncs are single-threaded; its matmul and linear algebra use OpenBLAS threads (OPENBLAS_NUM_THREADS=1 makes NumPy fully single-threaded). Typhon.NumPy parallelizes element-wise work above 131,072 elements and its matmul (TYPHON_NUMPY_THREADS=1 makes it single-threaded). "Best vs best" divides NumPy's faster configuration by Typhon's faster configuration. RAM is measured in the default configurations.
